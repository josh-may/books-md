## Communication

- Be simple and concise.
- Use the active voice.

## Git and GitHub

- Create a local commit after completing and verifying a meaningful milestone
  (such as a substantial feature, fix, or refactor), so work is easy to review
  and rewind. Use descriptive commit messages and include only related changes.
- If the project has no remote, create a private GitHub repository when it is
first pushed.

## Workspace layout

- Keep application code in `code/`. Run application commands from that folder.
- Keep local environment values in `code/.env`. Add `.env` to the repository’s Git ignore rules when initializing Git.
- Keep `AGENTS.md` at the workspace root for workspace instructions.
